关于 MLA 机制效果的小体量复现、机理分析与针对性改进

对外主文档。配套：实验方案 · 测试结论 · 参考结果 · 操作手册 · 返回 readme

单卡 6 GB 显存、64M 级模型、1.5 亿 token 预算。项目分三层：单层算子基准（上下文 2K–32K、潜维 128–384、头数 8–32、批大小 1–32）测绘吸收式 MLA 的盈亏边界；64M 整模型五组对照（补等缓存量级的 GQA-2 与无 QK-Norm 的完整 MLA）判定质量代价；两项针对性改进（潜空间 RMSNorm、分块解耦吸收解码）验证前两层定位到的成因。不复现 DeepSeek-V2 的训练配方。

测量环境：RTX 4050 Laptop，6140.5 MB 显存，BF16，PyTorch 2.10 + CUDA 12.6。时钟未锁定（实测 SM 约 2310 MHz，随负载浮动），架构间时延只取同进程交替测量的配对差值。

一、综述

MLA（Multi-head Latent Attention）自 DeepSeek-V2 提出后[1]，被广泛引用为「压缩 KV cache 且不损失性能」的注意力方案，其参数效率与推理加速在多个公开工作中被复述[6][7][8]。这些结论各有成立条件，而条件常被省略。先把 DeepSeek-V2 摘要的三项收益拆开：

  1. KV cache 减少 93.3% 相对 DeepSeek 67B 稠密基线成立，是本项目可独立复核的一项。
  2. 训练成本降低 42.5% 主要来自 DeepSeekMoE 的稀疏激活（236B 总参只激活 21B），不归功于注意力改动。
  3. 最大生成吞吐提升至 5.76 倍 是 MLA 释放显存换取超大并发批大小（叠加 FP8 权重、KV 平均 6 bit 量化与 8 卡 H800 服务配置）与 MoE 低激活计算的结果，不是单请求端到端的加速。

本项目在可完全重现的规模上检验后两项的条件，回答四个问题：压缩比是否按公式成立、参照系是谁；吸收相对朴素在同一硬件上何时快、何时慢；64M 级模型的质量代价有多大、来源是什么；对定位到的成因逐条修正，收益有多大。

主要发现六项。

  1. 压缩比按公式成立，但参照系是 MHA。 模型级每 token 每层 432 元素对 1536，3.556×；单层基准在 d_h=64 下 288 对 1024，同一比值。与等缓存量级的 GQA-2（384）相比 MLA 反而略大，压缩比的比较对象决定结论方向。
  2. 单请求下吸收不省时，原因不在缓存读取量。 d_c=256 时 decode 慢 31–35%、prefill 慢 118–135%，三档上下文比值几乎不动。吸收把注意力内积维抬到 d_c+d_rope=288，越过 Ada 架构 FlashAttention-2 的 256 维上限，SDPA 回退到慢速路径，这才是主因。
  3. 盈亏边界由潜维与批大小两个方向共同移动。 d_c 降至 128 时 32K 下比值 0.965（探索性观测），压缩比同时升至 6.40×；批大小增至 4 附近吸收即与朴素交叉，B=32 时 12.48 对 23.12 ms，提速 1.85×。
  4. 质量代价可量化且可归因。 同语料同预算下 MLA 验证困惑度比 MHA 高 14.19%（含 QK-Norm）与 14.78%（不含），且高于等缓存 GQA-2 的 9.6428。三条成因指向缺失的潜空间归一化、两级低秩初始化的方差失配与共享位置键容量。
  5. 潜空间前置 RMSNorm 补回大部分质量。 只增 3,072 参数（0.004%），验证 PPL 由 10.4911 降至 9.4682，优于等缓存 GQA-2，且不破坏吸收。
  6. 分块解耦吸收解码消除内核回退。 单层 B=1、32K 由 5.115 降至 2.684 ms（相对 SDPA 1.91×）；B=32、16K 为 6.920 ms（相对 MHA 1.54×、相对朴素 3.34×）；整模型 4K/B=32 聚合吞吐 1,045.8 token/s，相对 MHA 提高 79.1%。

本报告不判定 MLA 与 MHA 孰优。64M 级模型的质量上限由规模主导，全部结论限于所测的规模、批大小与内核条件。

二、实验原理

2.1 出发点：KV cache 随上下文线性增长

自回归推理的瓶颈之一是 KV cache 的显存占用与访存量。标准多头注意力（MHA）每 token 每层缓存全部键与值，元素数为 2 · n_h · d_h；GQA 令 n_g 组查询头共享一组键值，降为 2 · n_g · d_h，n_g=1 即 MQA[2]。MLA[1] 不减少组数，而是把键值联合压进低秩潜向量 c_t（d_c 维），并把位置信息拆到各头共享的解耦键 k_t^R（d_rope 维），缓存降为 d_c + d_rope，与头数无关。

本项目模型级取 d=768、n_h=8、d_h=96、d_c=384=4·d_h、d_rope=48=d_h/2，即 MLA 432、MHA 1536、GQA-4 768、GQA-2 384、MQA 192（MQA 未训练，仅按公式列出）。单层基准取 d_h=64、d_c=256、d_rope=32，即 MLA 288、MHA 1024。

2.2 缓存判据

令 MLA 优于 GQA-n_g，得

d_c + d_rope < 2 · n_g · d_h      ⇔      n_g > (d_c + d_rope) / (2 · d_h)

代入模型级取值，临界线为 n_g = 2.25：MLA 对 MHA 为 3.556×，对 GQA-4 为 1.778×，对 GQA-2 为 0.889，即不如 GQA-2。这条式子是所有「压缩 4–7 倍」类表述的参照，引用时必须带基线。

2.3 吸收式与朴素式，及吸收成立的三条必要条件

朴素实现每步把历史潜向量经 W_UK 展成完整键、经 W_UV 展成值，乘加量 O(L · n_h · d_h · d_c)，并物化 2 · L · n_h · d_h 元素。吸收实现利用矩阵结合律，把 W_UK 折进查询、把 W_UV 移到输出侧，注意力直接在 d_c 维空间内完成，乘加量降为 O(n_h · d_h · d_c)，与上下文长度无关。

(q_t^C)ᵀ W_UK c_s = (q'_t^C)ᵀ c_s ,   q'_t^C = W_UKᵀ q_t^C ∈ R^{d_c}
c_t      = W_DKV h_t              # 潜向量，d_c 维，即缓存内容
k_t^C    = W_UK c_t               # 内容键（朴素路径才展开）
k_t^R    = RoPE(W_KR h_t)         # 解耦键，各头共享
cache    = { c_t, k_t^R }

成立需三个条件同时满足。

  1. 位置编码须解耦。 内容键上若叠加随位置变化的旋转阵，W_UK 无法并入查询，且每个前缀 token 的键都要重算。
  2. Softmax 缩放分母保持 d_h + d_rope。 左右内积数值恒等，分母不必随潜空间维度改写；改写即不等价。
  3. 键侧归一化须线性或前移。 逐头 QK-Norm 的分母 ‖W_UK c_s‖ 非线性依赖 c_s，吸收不再成立；把 RMSNorm 前置到写入缓存之前的 c_t 上则兼容（见 5.1）。

2.4 Roofline 与混合路径

RTX 4050 的 HBM 带宽 192 GB/s、BF16 有效峰值约 38 TFLOP/s，Roofline 拐点为 I ≈ 198 FLOP/B。单请求短序列的解码落在 GEMV 区，算术强度低，受内核启动与访存延迟支配，吸收省下的物化流量不足以抵掉扩大的内积维；批大小上来后缓存读取成为主项，3.556× 的访存压缩才转化为吞吐。prefill 阶段吸收反而把二次项内积维由 d_h 扩到 d_c，故工程实现普遍采用 prefill 走朴素、decode 走吸收的混合路径，本项目的 MLAAttention 即按此调度：两条路径共用同一套参数，KV cache 以 {"c": [B, L, d_c], "k_rope": [B, 1, L, d_rope]} 管理，训练与 prefill 用朴素路径，decode 切吸收路径。

三、实验方案

3.1 单层算子基准

三种实现参数名与形状一致，共用同一套 SDPA 与掩码逻辑，固定 d_h=64、d_c=256、d_rope=32、单层、BF16。

实现每 token 每层缓存位置编码对照角色
MHA1024 元素 / 2 KiB全维 64时延与显存基线
朴素 MLA288 元素 / 576 B解耦 32每步全量展开，为时延参照
吸收 MLA288 元素 / 576 B解耦 32潜空间直算，回退与改进的对象

扫描四个维度：上下文 2K、16K、32K；d_c 取 384、256、192、128；n_h 取 8、16、32；批大小 B 取 1、4、8、16、32。每点多轮重复取中位数，prefill 与 decode 分别计时。

3.2 整模型五组

共同骨架为 d=768、8 层、SwiGLU 中间维 2432、词表 6400、训练长度 512；同一语料（MiniMind 同源中文部分）、同一 token 预算（每步 8192 token、共 18310 步，合计 1.5 亿 token）、同一优化器与调度、同一 seed 集合（42、43）。

配置键值组织缓存/层QK-Norm参数量可用推理路径
MHA8 组1536启用68,630,784标准
GQA-44 组768启用63,912,192标准
GQA-22 组384启用61,552,896标准
MLA（含 QK-Norm）潜向量 384 + 解耦 48432启用68,925,696仅朴素
MLA（无 QK-Norm）同上432关闭68,924,160朴素与吸收

补 GQA-2 的理由是等缓存量级：384 对 432，比 GQA-4 的 768 更接近 MLA，用来判断 MLA 在同样缓存预算下是否比头共享更划算。补无 QK-Norm 组的理由是执行路径：QK-Norm 组只能走朴素，无法在这三组配置内回答吸收的时延问题。MLA 在 MHA、GQA 三组上开启 q_norm、k_norm 是为结构对齐，DeepSeek-V2 的 MLA 结构本身不含这一项，因此含 QK-Norm 的那组不是对论文结构的复现。

3.3 测量口径

  • 时延按批大小分档测量，B=1 至 32；聚合吞吐按纯解码速率 B / t_step 折算。
  • 时钟未锁定，nvidia-smi -lgc 返回权限不足，同一检查点两次测量可差 5.8%。模型级架构间时延用 eval_paired.py 在同一进程内交替测量，只取配对差值；层级基准为同结构同形状的独立计时对照。绝对毫秒数不跨时段比较。
  • 32K 上下文需分块 prefill（块长 1024），一次性前向的显存峰值超出 6 GB。
  • 每点多轮重复取中位数，不用单次测量。
  • 缓存量按 1 MiB = 2^20 B 计，峰值显存按工具报告的 MB 计。
  • 汇总表由 scripts/ 下的脚本从原始 jsonl 汇总，不手写；记录留存情况见下一条。
  • 数据可得性：data/results 与 data/runs 提交的原始记录覆盖整模型 MHA、GQA-4、MLA（含 QK-Norm）各两组 seed，归档的无 QK-Norm 组评测，以及单层 2K/16K/32K 上下文基准与缓存基准。GQA-2、批大小扫描、8K 长上下文与第 5 章两项改进的原始记录未随仓库提交，复核需按 run_all.py 重跑。

四、实验结果

4.1 缓存压缩：两条独立路径给出同一比值

模型级逐元素核验（data/results/model/tables/cache_bench.json，8 层、4096 token）显示，强制键张量随输入降为 BF16 后，MHA 与 MLA 均为 16 bit/元素：缓存元素数为 50,331,648 与 14,155,776，占用 96.0 MiB 与 27.0 MiB，比值 3.556×。单层基准取 d_h=64、d_c=256，每 token 每层 1024 与 288 元素，推到 32K 即 64.0 MiB 与 18.0 MiB，同一比值。

两条路径的配置不同（d_h=96, d_c=384 与 d_h=64, d_c=256），却给出同一个数，说明压缩量只由「潜维 + 解耦维」占「每 token 每层键值元素数」的比例决定，与实现细节无关。

注：MHA、GQA-4 与含 QK-Norm 的 MLA 各有两组 seed，验证 PPL 极差在 0.03–0.25 之间；GQA-2 为 seed 42 单组实测。参考系不是同参数量：MLA 比 MHA 多 294,912 参数，GQA-4 比 MHA 少 4,718,592，GQA-2 更少，故这张表是「参数量相差 10.3% 以内」的可比比较，不是等参数比较。

基础复现的 MLA 参数量略高于 MHA，困惑度却显著高于 MHA，也高于缓存只有 384 的 GQA-2。三条成因：

  1. 缺失潜空间独立 RMSNorm。 DeepSeek-V2 在 c_t 升维前施加 RMSNorm(c_t) 稳定瓶颈尺度，基础实现省掉了这一层，W_UK·W_DKV 退化为无非线性激活的双线性连乘，奇异值条件数变差，短程收敛变慢。
  2. 两级低秩初始化方差失配。 全网统一 N(0, 0.02²) 初始化，未对两级连乘做方差缩放，叠加解耦后内容与位置两条支路的梯度尺度失衡。
  3. 小模型共享位置键容量受限。 8 头共用单一 48 维 k_t^R，GQA-2 保留两组 96 维全维 RoPE 键，在 512 短序列下局部语法与位置建模相对占优。

QK-Norm 的位置也由此确定：开启只令验证 PPL 降 0.054（小于各组 0.03–0.25 的种子波动），却使训练吞吐由 18,726 降至 15,247 token/s（−18.6%，墙钟 2.22 h 增至 2.73 h），并使吸收路径不可用。它是为结构对齐付的成本，不是质量收益。

五、针对性改进

5.1 架构侧：潜空间 RMSNorm 与低秩初始化修正

针对 4.5 定位的三条成因，把独立 RMSNorm(384) 前置到潜向量写入缓存之前（缓存内容变为 c̃_t = RMSNorm(W_DKV x_t)），关闭键侧 QK-Norm，并把 w_uk、w_uv 的初始化标准差按 1/√2 缩放对齐两级连乘的方差。因为 W_UK · c̃_t 对缓存仍是线性的，这一改动与矩阵吸收兼容；全模型只增 3,072 参数（0.004%）。

5.2 算子侧：规避 SDPA 维度回退的分块解耦吸收解码

针对 4.3 定位的 head_dim > 256 回退，在 decode 步（T=1）把吸收路径拆成两次规整的 GEMM：潜空间内积 q'_t^C · (C_{1:L})ᵀ（d_c=256，规整维度）与位置内积 q_t^R · (K_{1:L}^R)ᵀ（32 维），FP32 累加、缩放后做一次 Softmax，再乘 C_{1:L} 与 W_UV。两次 GEMM 的维度都落在通用内核的支持范围内，不触发慢路径，也不需要重训，数值相对误差小于 1.2×10⁻⁶。

def split_absorbed_decode(q_nope, q_rope, c_all, k_rope_all, w_uk, w_uv, w_o, scale):
    q_abs    = torch.einsum("bhd,hde->bhe", q_nope.squeeze(1), w_uk)          # [B,H,d_c]
    scores_c = torch.matmul(q_abs, c_all.transpose(-1, -2))                   # [B,H,L]
    scores_r = torch.matmul(q_rope.squeeze(2), k_rope_all.squeeze(1).transpose(-1, -2))
    attn = torch.softmax((scores_c.float() + scores_r.float()) * scale, -1).to(c_all.dtype)
    z = torch.matmul(attn, c_all)                                            # [B,H,d_c]
    tmp = torch.einsum("bhe,hde->bhd", z, w_uv)
    return torch.einsum("bhx,phx->bp", tmp, w_o).unsqueeze(1)                  # [B,1,d]

5.3 结论与选型建议

  1. 缓存压缩按公式成立，参照系须写明。 3.556× 是相对 MHA；相对 GQA-4 为 1.778×，相对等缓存的 GQA-2 反而不如。工程上兑现的是 8K × 32 并发下 MHA 的 OOM 与 MLA 的 2,184 MB 峰值。
  2. 吸收快慢是条件命题，不是结构优劣。 受制于 Roofline 算术强度与内核维度上限：B=1 时比朴素慢 31–35%；B ≥ 8 时比朴素快；改用分块算子后，B ≥ 8 区间亦快于 MHA。
  3. 潜空间归一化是低成本必要项。 3,072 参数换来 1.02 的 PPL 下降，并保住吸收能力；键侧 QK-Norm 应避免，若须保留则按 QK-Normed MLA[10] 的思路把静态权重折入查询。
  4. 选型建议。 长上下文高并发在线服务宜用「潜空间 RMSNorm + prefill 朴素 / decode 专用吸收算子」；从零训练宜在潜向量上做归一化，不宜在解压后的键上做 QK-Norm；单请求短上下文（小于 2K）的端侧部署，结构更简单的 GQA-2/GQA-4 更划算；存量模型迁移优先考虑 TransMLA[6] 或 MHA2MLA[7]。

七、局限与适用边界

  1. 规模只到 64M、1.5 亿 token、训练长度 512。质量差异在该规模下可重复，但不能外推到 1B 以上；训练长度限制也意味着长上下文只做了推理侧验证。
  2. 模型级从未做同权重下的吸收与朴素对照。带 QK-Norm 的组只能走朴素，能走吸收的那组权重已于 2026-11-18 删除，其吸收时延取自归档评测（同一 run_id 两次评测，9.78–10.45 ms），只作机制说明。因此「吸收在模型级更慢」严格说只有单层证据。
  3. 批大小测到 32。再大需更多显存或流式解码；8K × 32 时 MHA 已 OOM，该档只有 MLA 与 GQA 的对照。
  4. 时钟未锁定，绝对毫秒数跨时段不可比，架构间只取配对差值；seed 只有两个，差值小于极差之和时一律记为未观测到显著差异。
  5. 查询侧为满秩投影，未实现论文的低秩分支（W_DQ 后接 W_UQ）[1]。该缺失不作用于 KV 侧，不影响缓存与吸收的测量，但参数量与原始结构不完全对齐。
  6. d_c=128 与改进后的整模型质量只测了验证/测试困惑度，没有下游任务评测。

后续可补的工作三项：把改进后的整模型放回 8K 以上上下文与更大批大小；以 Triton 写片上融合解码内核，消除分块算子对 L 的得分写回；在 1B 级规模上检验潜空间归一化是否仍是必要项。

复现入口：python run_all.py --dry-run 打印全部命令，python run_all.py 依次执行检查、切分、训练、评测、层级基准、汇总与出图。环境、目录约定与故障排查见 readme 与 guide，逐条数字与推导见 reference_results.md，测试结论明细见 conclusion.md，实验设计见 experiment_plan.md。
